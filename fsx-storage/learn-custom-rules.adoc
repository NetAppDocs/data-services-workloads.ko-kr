[role="lead"]
사용자 지정 규칙을 사용하면 잘 설계된 대시보드에서 NetApp 모범 사례와 함께 자체 아키텍처 표준을 설정, 확인 및 적용할 수 있습니다.



[[overview]]
== 개요

규칙 작성기를 사용하면 일반 언어로 사용자 지정 규칙을 만들 수 있습니다. 이러한 규칙은 모든 리소스에 대해 검사됩니다. 사용자 지정 규칙을 통해 기본 규칙에서 다루지 못할 수 있는 조직의 표준, 위험 한도 및 운영 요구 사항을 적용할 수 있습니다.


NOTE: 계정 관리자가 AI 기능을 비활성화한 경우 새 규칙을 만들거나 기존 규칙을 수정할 수 없습니다. 이미 예약된 규칙은 계속 실행됩니다. link:../admin/manage-genai-features.html["AI 기능 관리에 대해 알아보기"].



[[how-custom-rules-work]]
== 사용자 지정 규칙 작동 방식

사용자 지정 규칙은 AI를 사용하여 일반 언어로 된 지침을 명확하고 구조화된 규칙으로 변환합니다. AI는 사용자의 요청을 번역하고, 규칙을 제안하고, 지침을 어떻게 이해했는지 설명하고, 규칙을 저장하거나 예약하기 전에 승인을 요청합니다. 이 프로세스를 통해 다음과 같은 사항을 보장할 수 있습니다.

* 규칙은 명확하게 정의되어 있으며 오류 여부를 검사합니다
* 사용자 정의 코드는 실행되지 않습니다
* 규칙을 승인하기 전에 정확히 어떤 항목이 평가될지 검토할 수 있습니다.
* 각 사용자 지정 규칙에는 평가할 리소스 유형, 조건 논리, 심각도, 평가 일정 및 해결 지침이 포함됩니다.




[[before-you-begin]]
== 시작하기 전에

사용자 지정 규칙을 만들고 실행하기 전에 다음 사항을 확인하십시오.

AWS 자격 증명:: AWS 환경에 대한 읽기 전용 액세스 권한입니다. 사용자 지정 규칙은 보안 경계로 읽기 전용 권한을 요구합니다. link:add-credentials.html["Workload Factory에 AWS 자격 증명 추가"].
ONTAP 자격 증명:: 읽기 전용 권한을 가진 FSx 뷰어 사용자입니다. Workload Factory는 읽기 전용 사용자가 없는 경우 각 FSx for ONTAP 파일 시스템에 해당 사용자를 생성하여 평가를 수행할 수 있도록 합니다.
링크 또는 에이전트:: AWS API에서 접근할 수 없는 설정을 확인하기 위해 ONTAP에 직접 연결해야 하는 규칙에만 필요합니다. link:create-link.html["링크를 사용하여 FSx for ONTAP 파일 시스템에 연결합니다."].




[[limitations]]
== 제한 사항

* 규칙은 문제를 자동으로 해결할 수 없습니다. 제공된 지침을 사용하여 규정을 준수하지 않는 리소스를 직접 수정해야 합니다.
* 각 규칙은 한 가지 유형의 리소스만 검사하지만, 광범위한 리소스에 적용될 수 있습니다. 예를 들어, 하나의 규칙으로 여러 리전, 모든 리전 또는 여러 계정의 볼륨을 평가할 수 있습니다. 서로 다른 유형의 리소스를 평가하려면 별도의 규칙을 생성하십시오.
* 과도한 스캔을 방지하기 위해 규칙은 최대 한 시간에 한 번만 실행됩니다.
* 규칙은 환경을 읽기만 할 수 있으며 변경할 수는 없습니다.
* 나중에 규칙 카탈로그에서 이러한 설정을 업데이트할 수 있습니다.




[[rule-lifecycle]]
== 규칙 수명 주기

사용자 지정 규칙은 다음 단계를 거쳐 진행됩니다.

진행 중:: 규칙 생성 또는 확인.
생성에 실패했습니다:: 규칙을 생성할 수 없습니다. 채팅에서 규칙을 다시 열고 편집을 계속할 수 있습니다.
초안:: 저장되었지만 아직 일정이 잡히지 않았습니다.
검증된 초안:: 유효성 검사를 통과했으며 저장하거나 예약할 수 있습니다.
편집:: 기존 규칙의 초안을 업데이트하는 중입니다. 변경 사항을 저장할 때까지 현재 예약된 규칙은 계속 실행됩니다.
예약됨:: 활성화되어 있으며 정해진 일정에 따라 실행됩니다.
비활성화됨:: 일시 중지되었지만 삭제되지는 않았습니다. 다시 활성화할 수 있습니다.
삭제됨:: 영구적으로 제거되었습니다.




[[custom-rule-examples]]
== 사용자 지정 규칙 예시

운영 볼륨 보호:: "'Prod' 태그가 있는 모든 볼륨에는 스냅샷 정책이 설치되어 있어야 합니다."
+
--
이 규칙은 회사 요구 사항에 따라 프로덕션 볼륨을 보호하기 위해 자동으로 스냅샷을 생성합니다.

--
아카이브 볼륨 티어링:: "'Archive' 태그가 있는 모든 볼륨에는 계층화 정책이 'All'로 설정되어야 합니다."
+
--
이 규칙은 보관된 데이터를 더 저렴한 스토리지로 자동으로 이동하여 비용을 절감합니다.

--
파일 시스템 명명 표준:: "모든 파일 시스템은 명명 규칙 'fsx-{environment}-{application}'을 따라야 합니다."
+
--
이 규칙은 파일 시스템이 조직의 명명 규칙을 준수하여 관리 및 비용 할당을 용이하게 하는지 검증합니다.

--
