= FSx for ONTAP 파일 시스템용 스토리지 VM을 생성합니다
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
NetApp Workload Factory에서 워크로드에 대한 스토리지 및 데이터 서비스에 가상으로 액세스할 수 있도록 FSx for ONTAP 파일 시스템용 스토리지 VM(SVM)을 생성합니다.

.이 작업 정보
스토리지 VM은 Workload Factory Storage의 각 워크로드에서 데이터에 액세스하는 데 사용할 수 있는 격리된 파일 서버입니다. 각 SVM에는 데이터 관리 및 액세스를 위한 고유한 관리자 자격 증명과 엔드포인트가 있습니다.

SVM을 사용하면 FSx for ONTAP에서 데이터에 액세스할 때 클라이언트와 워크스테이션은 SVM의 엔드포인트(IP 주소)를 사용하여 SVM에서 호스팅하는 볼륨, CIFS/SMB 공유 또는 iSCSI LUN을 마운트합니다.

.시작하기 전에
파일 시스템별로 지원되는 스토리지 VM 수를 확인하십시오. 파일 시스템별 최대 SVM 수는 AWS 설명서의 link:https://docs.aws.amazon.com/fsx/latest/ONTAPGuide/managing-svms.html#max-svms["FSx for ONTAP 스토리지 가상 머신 관리"^]을(를) 참조하십시오.



[[create-a-storage-vm]]
== 스토리지 VM 생성

Workload Factory 콘솔에서 스토리지 VM을 생성할 수 있습니다. 또한 Codebox에서 제공되는 다음 툴을 사용할 수도 있습니다: REST API, CloudFormation 및 Terraform. link:../admin/use-codebox.html#how-to-use-codebox["Codebox를 활용한 자동화 방법을 알아보세요"^].


NOTE: Codebox에서 Terraform을 사용할 경우, 복사하거나 다운로드하는 코드에는  `fsxadmin` 및  `vsadmin` 암호가 숨겨져 있습니다. 코드를 실행할 때 암호를 다시 입력해야 합니다.

.단계
. link:https://console.netapp.com["NetApp Console"^]에 로그인하십시오.
. 메뉴 image:workloads-menu-icon.png["햄버거 메뉴 아이콘은 Workload Factory의 메뉴 항목인 Workloads로 이동하는 데 사용됩니다."], *워크로드* > *스토리지* > *FSx for ONTAP*을 선택합니다.
. *FSx for ONTAP*에서 파일 시스템의 작업 메뉴를 선택한 다음 *관리*를 선택합니다.
. 파일 시스템 개요의 스토리지 VM에서 *스토리지 VM 생성*을 선택합니다.
. 스토리지 VM 생성 페이지의 스토리지 VM 구성에서 다음 정보를 제공하십시오:
+
.. *이름*: 스토리지 VM의 이름을 입력하세요.
.. *스토리지 VM 자격 증명*: 이 스토리지 VM의  `vsadmin` 사용자 암호를 제공하거나 파일 시스템의  `fsxadmin` 사용자 자격 증명을 사용하십시오.
.. *루트 볼륨 보안 스타일*: 데이터에 액세스하는 클라이언트 유형(UNIX(Linux 클라이언트), NTFS(Windows 클라이언트) 또는 혼합)에 따라 루트 볼륨 보안 스타일을 선택하십시오.
.. *태그*: 선택 사항으로 최대 50개의 태그를 추가할 수 있습니다.


. *생성*을 선택합니다.
