= OCI NSS 시스템에 대한 구성 분석
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
NetApp Workload Factory는 OCI NSS 시스템 구성을 정기적으로 분석하여 구성 문제가 있는지 확인합니다. 문제가 발견되면 Workload Factory는 문제가 무엇인지 보여주고, 스토리지 환경이 최상의 성능, 비용 효율성 및 모범 사례 준수를 달성하도록 무엇을 변경해야 하는지 설명합니다.

주요 기능은 다음과 같습니다:

* 일일 구성 분석
* 자동 모범 사례 검증
* 사전 예방적 관찰 가능성
* 인사이트를 실행으로
* OCI Well-Architected Framework 어드바이저




[[how-it-works]]
== 작동 방식

Workload Factory는 지원되는 클라우드 스토리지 배포 환경에서 매일 워크로드를 분석합니다. 이 분석을 통해 아키텍처가 잘 설계된 상태, 인사이트 및 권장 사항을 제공합니다.

일일 분석이 완료되면, 배포에 대한 Well-architected 대시보드에서 구성이 "최적화됨" 또는 "최적화되지 않음"으로 표시됩니다. 구성 문제는 범주별로 정리되어 있으며, 권장 사항도 함께 제공됩니다. Workload Factory는 권장 변경 사항을 구현하는 데 도움이 되는 자세한 지침을 제공합니다.

사용 환경에 적용되지 않는 구성에 대한 분석은 제외할 수 있습니다. 이렇게 하면 불필요한 알림과 부정확한 최적화 결과를 방지할 수 있습니다.



[[why-it-matters]]
== 중요한 이유

Workload Factory는 지속적인 평가와 권장 사항 및 문제 해결을 결합하여 대규모 스토리지, 데이터베이스 및 VMware 환경에 최적의 솔루션을 적용합니다. 자동화된 수정 기능은 인적 오류를 줄이고, 일관된 관리를 보장하며, 워크로드 인프라 전반의 성능과 안정성을 유지합니다.

[[best-practices-and-recommendations-for-storage-workloads]]
== 스토리지 워크로드에 대한 모범 사례 및 권장 사항

잘 설계된 대시보드는 스토리지 구성을 ONTAP 모범 사례 및 AWS Well-Architected Framework에 따라 평가합니다. 이 평가는 또한 개선 사항 및 수정 사항을 권장합니다.

잘 설계된 분석은 프레임워크의 다음 핵심 요소인 _안정성_, _보안_, _운영 우수성_, _비용 최적화_ 및 _성능 효율성_으로 구성을 분류합니다.


NOTE: 현재 Workload Factory는 모든 구성에 대해 워크로드별 권장 사항을 제공하지 않습니다. 특정 워크로드 요구 사항에 맞게 구성을 조정하십시오.



[[reliability]]
=== 안정성

안정성은 중단이 발생하더라도 워크로드가 의도된 기능을 정확하고 일관되게 수행하도록 보장합니다.

* *파일 오브젝트 용량*
+
볼륨 용량 제한에 도달하지 않도록 파일 용량 임계값을 높여야 합니다. 파일 용량(inode)이 부족하면 볼륨에 추가 데이터를 기록할 수 없습니다. Workload Factory는 새 파일 생성을 위해 파일 용량 사용률을 80% 미만으로 유지하는 것을 권장합니다.

* *스냅샷 정책*
+
효율적인 백업과 빠른 복원을 위해 로컬 스냅샷을 예약하세요. 스냅샷은 볼륨의 즉각적인 특정 시점 이미지입니다. 이 권장 사항은 데이터베이스 환경에는 적용되지 않습니다.

* *SSD 용량 여유 공간*
+
SSD 스토리지 계층의 사용률은 80%를 초과해서는 안 됩니다. 이는 용량 풀 스토리지 계층의 데이터 읽기 및 쓰기 작업에 영향을 미치고 파일 시스템의 처리량 용량에도 영향을 줄 수 있습니다. 용량이 부족해지면 데이터 볼륨은 읽기 전용이 됩니다. 새 데이터를 쓰려는 서비스도 실패합니다.





[[operational-excellence]]
=== 운영 우수성

운영 우수성은 워크로드가 효과적으로 운영 및 모니터링되고 사용자 요구 사항을 지원할 수 있도록 보장합니다.

* *호스트에서 볼 수 있는 용량 보고*
+
호스트에서 볼 수 있는 용량 보고 기능을 활성화하여 볼륨 수준에서 스토리지 사용량을 더 잘 파악할 수 있도록 하십시오.

* *볼륨 용량 여유 공간*
+
성장을 수용하고 예상치 못한 용량 문제를 방지하기 위해 볼륨 용량 여유분을 10%로 설정해야 합니다.





[[cost-optimization]]
=== 비용 최적화

비용 최적화는 비용을 낮게 유지하면서 비즈니스에 가장 큰 가치를 얻을 수 있도록 도와줍니다.

* *콜드 데이터 티어링* 활성 데이터는 SSD 티어에 유지하고 스냅샷 데이터만 용량 티어로 이동하는 스냅샷 전용 티어링 정책을 사용하십시오. 이 방식을 통해 데이터베이스 워크로드의 지연 시간을 최소화하면서 스토리지 비용을 절감할 수 있습니다. 7일의 냉각 기간 후에 스냅샷 데이터를 티어링하십시오.
* *스냅샷 정리*
+
더 이상 필요하지 않은 오래된 스냅샷이나 수동으로 생성한 스냅샷을 삭제하십시오. 특히 SLA 또는 복구 요구 사항에 필요하지 않은 스냅샷은 삭제하면 비용을 절감하고 불필요한 항목을 줄일 수 있습니다.

* *스토리지 효율성*
+
스토리지 효율성(컴팩션, 압축, 중복 제거)을 활성화하여 스토리지 활용도를 최적화하고 SSD 계층 비용을 절감하십시오.
