= NetApp Workload Factory 링크 관리
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Workload Factory 계정에 연결된 링크를 관리합니다. FSx for ONTAP 파일 시스템 또는 OCI NetApp Storage Service(OCI NSS) 시스템과 연결된 링크를 확인하고, 링크 인증에 사용되는 암호를 제공하며, NetApp Console에서 링크를 제거할 수 있습니다.

link:../setup/links-overview.html["링크에 대해 자세히 알아보세요."]

사용자 인터페이스는 새로운 링크 버전이 출시되면 자동으로 알려주고 업그레이드 방법을 안내합니다.



[[view-the-links-associated-with-your-account]]
== 계정과 연결된 링크를 확인합니다

현재 계정에 연결된 링크를 확인할 수 있습니다.

.단계
. 메뉴 image:workloads-menu-icon.png["햄버거 메뉴 아이콘은 Workload Factory의 메뉴 항목인 Workloads로 이동하는 데 사용됩니다."], *관리* > *링크*를 선택합니다.
+
기존 링크는 링크 페이지에 표시됩니다.

. 링크와 연결된 스토리지 시스템을 보려면 연결된 리소스 섹션에서 *보기* 버튼을 선택하십시오.
. 링크에 사용할 Amazon Resource Name(ARN)이 필요한 경우 ARN 필드 옆에 있는 _복사_ 아이콘을 선택하면 됩니다.




[[edit-a-link]]
== 링크 수정

NetApp Console에서는 링크를 편집할 수 없습니다. 링크를 변경해야 하는 경우 새 링크를 생성한 다음 해당 링크를 스토리지 시스템에 연결해야 합니다.


NOTE: 클라우드 공급자의 콘솔을 사용하여 AWS Lambda 또는 Oracle Cloud Functions 네트워크 구성(예: VPC, 서브넷 및 보안 그룹)을 편집할 수 있으며 변경 사항은 링크 또는 Functions 관리 UI에 반영됩니다. 그러나 이러한 변경은 AWS Lambda 또는 Oracle Cloud Functions와 ONTAP 간의 연결 문제를 일으킬 수 있으므로 권장되지 않습니다.



[[authenticate-a-link]]
== 링크 인증

Workload Factory 자격 증명에 대한 관리자 사용자 암호를 제공하거나 AWS Secrets Manager 또는 Oracle Vault의 비밀 키를 사용하여 링크를 인증하십시오.

* AWS Secrets Manager의 경우, 링크를 FSx for ONTAP 파일 시스템에 연결하려면 시크릿 이름 또는 AWS Secrets Manager 시크릿 ARN을 제공하십시오.
+

NOTE: 콘솔 에이전트를 사용할 때는 AWS Secrets Manager가 지원되지 않습니다.

* Oracle Vault의 경우, 링크를 OCI NetAApp Storage Service 시스템에 연결하려면 볼트 시크릿 OCID를 제공하십시오.



NOTE: 링크당 하나의 인증 방법만 지원됩니다. 예를 들어 AWS Secrets Manager를 사용한 링크 인증을 선택한 경우 나중에 인증 방법을 변경할 수 없습니다.

[role="tabbed-block"]
====
.Amazon FSx for NetApp ONTAP
--
.단계
. link:https://console.netapp.com["NetApp Console"^]에 로그인하십시오.
. 메뉴 image:workloads-menu-icon.png["햄버거 메뉴 아이콘은 Workload Factory의 메뉴 항목인 Workloads로 이동하는 데 사용됩니다."], *워크로드* > *스토리지* > *FSx for ONTAP*을 선택합니다.
. *FSx for ONTAP*에서 링크를 연결할 파일 시스템의 작업 메뉴를 선택한 다음 *관리*를 선택합니다.
. 파일 시스템 개요에서 *링크 인증*을 선택합니다.
. 인증 링크 페이지에서 인증 모드를 선택합니다.
+
** *Workload Factory*: 비밀번호를 두 번 입력하세요.
** *AWS Secrets Manager*: 시크릿 ARN을 입력하십시오.


. *적용*을 선택합니다.


--
.OCI NetApp 스토리지 서비스
--
.단계
. link:https://console.netapp.com["NetApp Console"^]에 로그인하십시오.
. 메뉴 image:workloads-menu-icon.png["햄버거 메뉴 아이콘은 Workload Factory의 메뉴 항목인 Workloads로 이동하는 데 사용됩니다."], *워크로드* > *스토리지* > *OCI NetApp 스토리지 서비스*를 선택합니다.
. *OCI NetApp 스토리지 서비스*에서 링크를 연결할 스토리지 풀의 작업 메뉴를 선택한 다음 *관리*를 선택합니다.
. 스토리지 풀 개요에서 *링크 인증*을 선택합니다.
. 인증 링크 페이지에서 인증 모드를 선택합니다.
+
** *Workload Factory*: 비밀번호를 두 번 입력하세요.
** *OCI Vault*: 시크릿 OCID를 입력하십시오.


. *적용*을 선택합니다.


--
====
.결과
링크가 인증되었으므로 고급 ONTAP 작업을 수행할 수 있습니다.

[[remove-a-link]]
== 링크 제거

환경에서 더 이상 사용하지 않는 링크를 제거할 수 있습니다. 링크가 제거되면 해당 링크를 사용하던 스토리지 시스템이나 기타 리소스는 특정 기능을 사용할 수 없게 됩니다.

참고로 해당 링크는 Workload Factory에서만 삭제되며 AWS 또는 Oracle 환경에서는 삭제되지 않습니다.

* FSx for ONTAP의 경우, Workload Factory에서 링크를 제거한 후 AWS 계정에서 Lambda 함수를 삭제해야 합니다.
* OCI NetApp 스토리지 서비스의 경우, Workload Factory에서 링크를 제거한 후 OCI 계정에서 함수 인스턴스를 삭제해야 합니다.


[role="tabbed-block"]
====
.Amazon FSx for NetApp ONTAP
--
.단계
. link:https://console.netapp.com["NetApp Console"^]에 로그인하십시오.
. 메뉴 image:workloads-menu-icon.png["햄버거 메뉴 아이콘은 Workload Factory의 메뉴 항목인 Workloads로 이동하는 데 사용됩니다."], *관리* > *링크*를 선택합니다.
+
기존 링크는 링크 페이지에 표시됩니다.

. 링크 페이지에서 삭제할 링크의 작업 메뉴를 선택한 다음 *Remove*를 선택합니다.
. 확실하다면 *제거*를 다시 선택하십시오.


자세한 내용은 AWS 설명서를 참조하십시오link:https://docs.aws.amazon.com/lambda/latest/dg/gettingstarted-awscli.html#with-userapp-walkthrough-custom-events-delete-function["Lambda 함수를 삭제합니다"].

--
.OCI NetApp 스토리지 서비스
--
.단계
. link:https://console.netapp.com["NetApp Console"^]에 로그인하십시오.
. 메뉴 image:workloads-menu-icon.png["햄버거 메뉴 아이콘은 Workload Factory의 메뉴 항목인 Workloads로 이동하는 데 사용됩니다."], *관리* > *링크*를 선택합니다.
+
기존 링크는 링크 페이지에 표시됩니다.

. 링크 페이지에서 삭제할 링크의 작업 메뉴를 선택한 다음 *Remove*를 선택합니다.
. 확실하다면 *제거*를 다시 선택하십시오.
