= VMware 워크로드 마이그레이션 어드바이저를 사용하여 VMware Cloud on AWS용 배포 계획을 생성합니다.
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
NetApp Workload Factory에 로그인하여 VMware 마이그레이션 어드바이저에 액세스하십시오. 마법사의 단계를 따라 사용자 요구에 맞게 사용자 지정된 배포 계획 또는 마이그레이션 계획을 생성합니다.

VMware Cloud로 마이그레이션할 때 마이그레이션 어드바이저를 사용하여 현재 온프레미스 vSphere 환경을 VMWare cloud로 마이그레이션할 수 있습니다.

Workload Factory에 액세스하려면 사용자 이름과 비밀번호가 있어야 합니다. 액세스 권한이 없는 경우 지금 계정을 만드십시오. 지침을 확인하십시오 link:quick-start-vmware.html["여기"].



[[create-a-deployment-plan-based-on-an-on-premises-vsphere-environment]]
== 온프레미스 vSphere 환경을 기반으로 배포 계획을 수립합니다.

온프레미스 vSphere 환경의 현재 가상 머신 구성을 AWS의 VMware Cloud에 있는 가상 머신으로 마이그레이션하고 사용자 지정 Amazon FSx for NetApp ONTAP 파일 시스템을 외부 데이터스토어로 사용할 수 있습니다.

.요구 사항
* 마이그레이션 어드바이저 VM 수집기(.csv 파일) 또는 RVTools(.xlsx 파일)를 사용하여 기존 시스템에서 인벤토리 파일을 생성해야 합니다.
* Workload Factory에 로그인하는 시스템에서 인벤토리 파일에 대한 접근 권한이 있어야 합니다.


.단계
. link:https://console.netapp.com["NetApp Console"^]에 로그인하십시오.
. 메뉴 image:workloads-menu-icon.png["햄버거 메뉴 아이콘은 Workload Factory의 메뉴 항목인 Workloads로 이동하는 데 사용됩니다."], *워크로드* > *VMware*를 선택합니다.
+
계획 센터가 표시됩니다.

. *계획 및 VMC 생성*을 선택합니다.
. 현재 VM 구성으로 Workload Factory를 채우는 데 사용할 인벤토리 파일 유형을 선택하고 *다음*을 선택합니다.
+
** VMware 데이터 수집기를 사용하여 생성한 .csv 파일을 사용하려면 *마이그레이션 어드바이저 VMware 데이터 수집기 사용*을 선택하십시오.
** RVTools를 사용하여 생성한 .xlsx 파일을 사용하려면 *RVTools 사용*을 선택하십시오.


+
"VMware Cloud 온보딩 준비" 페이지가 표시됩니다.

. _VM 구성 업로드_ 섹션에서 image:button-upload-file.png["업로드 버튼"]을(를) 선택하고 사용할 파일을 선택합니다.
+
** Migration advisor VM collector를 사용할 때 .csv 파일을 선택하십시오.
** RVTools를 사용할 때는 .xlsx 파일을 선택하십시오.


+
VM 요약 섹션은 인벤토리 파일에서 채워져 VM 수와 총 스토리지 용량을 반영합니다.

. _VM 인벤토리 고려 사항_ 섹션에서 마이그레이션할 VM 목록을 필터링하는 옵션을 선택합니다.
+
.. *VM 고려 사항*: VM의 작동 상태를 기준으로 .csv 파일에서 추출할 VM을 지정합니다. 모든 VM을 가져오거나, 켜짐, 꺼짐 또는 일시 중단 상태인 VM만 가져올 수 있습니다.
.. *VM 스토리지 고려 사항*: 온보딩된 각 VM에 대해 생성되는 데이터스토어의 크기를 현재 사용 중인 크기(권장)를 기준으로 할지 아니면 프로비저닝된 크기를 기준으로 할지 선택합니다.
+
외부 데이터 저장소는 Amazon FSx for NetApp ONTAP 파일 시스템 볼륨을 사용하여 구현될 예정입니다.

.. *VM 메모리 고려 사항*: 새로 추가되는 각 VM에 할당되는 메모리 크기를 현재 사용 중인 크기를 기준으로 할지(권장) 아니면 프로비저닝된 크기를 기준으로 할지 선택합니다.


. _VMware Cloud on AWS 배포 구성_ 섹션에서 필요한 VMware Cloud on AWS 구성에 대한 세부 정보를 입력합니다.
+
.. *지역*: VM 및 Amazon FSx for NetApp ONTAP 파일 시스템이 배포될 지역을 선택하십시오.
+
최적의 성능과 비용 효율성을 위해 일반적으로 기존 VMware Cloud on AWS SDDC가 배포된 지역과 동일한 지역을 사용합니다.

.. *VM 예상 성능 요구 사항*: 이 옵션은 RVTools를 사용할 때만 사용할 수 있습니다. Migration advisor VM collector가 환경에서 이 정보를 수집합니다. 배포할 새 VM에 적용할 다음 가상 머신별 평균 성능 매개변수를 제공하십시오.
+
*** *VM당 평균 IOPS*: 파일 시스템에 필요한 IOPS 수를 입력하십시오. 잘 모르겠으면 Amazon FSx for ONTAP 파일 시스템의 경우 SSD 스토리지 1GiB당 3 IOPS의 기본값을 사용할 수 있습니다. 예를 들어 2,000GiB 용량을 배포하는 경우 6,000 IOPS가 됩니다. 처음에는 더 작은 IOPS 설정으로 시작하는 것이 좋습니다. 파일 시스템 생성 후 워크로드를 마이그레이션하거나 배포하면서 프로비저닝된 SSD IOPS를 늘릴 수 있습니다.
*** *평균 I/O 블록 크기*: 읽기 또는 쓰기 작업을 포함하는 각 블록의 크기입니다. 기본 크기는 4KB입니다. 대규모 순차 읽기 및 쓰기 워크로드의 경우 더 큰 블록 크기가 더 적합할 수 있습니다. 희소 파일이나 대용량 파일에 소규모 임의 쓰기 작업을 수행하는 워크로드의 경우 더 작은 블록 크기가 더 나은 성능을 제공할 수 있습니다.
*** *평균 쓰기 비율*: 워크로드에서 쓰기 작업이 차지하는 비율입니다. 기본 비율은 쓰기 30%, 읽기 70%입니다.




. _VM 스토리지 용량 고려 사항_ 섹션에서 몇 가지 스토리지 옵션 중에서 선택하십시오.
+
.. *평균 데이터 축소 비율*: 세 가지 일반적인 데이터 축소 선택 값 중에서 선택하십시오. "1:1 - 축소 없음", "1:1.25 - 20% 축소" 또는 "1:1.5 - 33% 축소"를 선택하십시오.
.. *여유 용량 비율*: FSx for ONTAP 파일 시스템의 용량에 추가되는 용량 증가율을 백분율로 입력하십시오.
+
참고로, 20% 미만의 용량을 선택하면 보호 및 장기 백업을 위한 볼륨 스냅샷을 생성할 수 없습니다.



. *다음*을 선택하면 "VMware cloud on AWS 노드 구성" 페이지가 표시됩니다.
+
이 페이지에서는 예상 비용 절감 분석 및 권장 노드 유형을 사용하여 VMware cloud on AWS 클러스터 구성을 정의할 수 있습니다. 다음 항목을 구성할 수 있습니다.

+
.. *vSAN 아키텍처*: vSAN Express Storage Architecture(ESA) 또는 vSAN Original Storage Architecture(OSA) 아키텍처 중 어떤 것을 사용할지 선택하십시오.
.. *vSAN 내결함성*: 가상 머신에 필요한 내결함성 수준을 선택하십시오. 권장되는 "Auto"를 선택하거나 다양한 RAID 레벨 중에서 선택할 수 있습니다.
+
*** RAID-1 (FTT 1): 2개 이상의 디스크에 데이터 세트의 정확한 복사본(또는 미러링)으로 구성됩니다.
*** RAID-5 (FTT 1): 블록 수준 스트라이핑과 분산 패리티로 구성됩니다 - 패리티 정보는 3개 이상의 드라이브에 분산되어 저장되며 단일 디스크 장애를 견딜 수 있습니다.
*** RAID-5 (FTT 2): 분산 패리티를 사용하는 블록 수준 스트라이핑으로 구성됩니다 - 패리티 정보는 4개 이상의 드라이브에 분산되며, 동시에 발생하는 두 개의 디스크 장애를 견딜 수 있습니다.
*** RAID-6 (FTT 2): RAID 5에 패리티 블록을 하나 더 추가하여 확장한 버전으로, 모든 멤버 디스크에 두 개의 패리티 블록을 분산 배치하는 블록 레벨 스트라이핑 방식을 사용합니다. 4개 이상의 드라이브가 필요하며, 동시에 발생하는 두 개의 디스크 장애를 견딜 수 있습니다.


.. *노드 구성 선택 목록*: 노드에 사용할 EC2 인스턴스 유형을 선택하십시오.


. *다음*을 선택하면 "가상 머신 선택" 페이지에 이전 페이지에서 입력한 기준과 일치하는 가상 머신이 표시됩니다.
+
.. _선택 기준_ 섹션에서 배포할 VM에 대한 기준을 선택합니다:
+
*** 비용 및 성능 최적화를 기반으로 함
*** 로컬 스냅샷을 사용하여 복구 시나리오에서 데이터를 쉽게 복원할 수 있는 기능을 기반으로 합니다.
*** 두 가지 기준 모두에 기반: 우수한 복구 옵션을 제공하면서도 가장 낮은 비용


.. _가상 머신_ 섹션에서는 이전 페이지에서 제공한 기준과 일치하는 VM이 선택(체크)됩니다. 이 페이지에서 더 적거나 더 많은 VM을 온보딩/마이그레이션하려면 VM을 선택하거나 선택 해제하십시오.
+
*권장 배포* 섹션은 변경 사항이 있을 경우 업데이트됩니다. 참고로, 제목 행의 확인란을 선택하면 이 페이지의 모든 VM을 선택할 수 있습니다.

.. *다음*을 선택하십시오.


. *데이터스토어 배포 계획* 페이지에서 마이그레이션에 권장되는 VM 및 데이터스토어의 총 개수를 확인하십시오.
+
.. 페이지 상단에 나열된 각 데이터스토어를 선택하여 데이터스토어와 VM이 어떻게 프로비저닝되는지 확인하십시오.
+
페이지 하단에는 이 새 VM과 데이터스토어가 프로비저닝될 소스 VM(또는 여러 VM)이 표시됩니다.

.. 데이터 저장소 배포 방법을 이해하셨으면 *다음*을 선택하세요.


. *배포 계획 검토* 페이지에서 마이그레이션할 모든 VM에 대한 예상 월별 비용을 검토하십시오.
+
페이지 상단에는 배포된 모든 VM 및 FSx for ONTAP 파일 시스템에 대한 월별 비용이 표시됩니다. 각 섹션을 확장하면 "권장 Amazon FSx for ONTAP 파일 시스템 구성", "예상 비용 분석", "볼륨 구성", "크기 산정 가정" 및 기술 "면책 조항"에 대한 세부 정보를 볼 수 있습니다.

. 마이그레이션 계획에 만족하시면 몇 가지 옵션이 있습니다:
+
** VM을 지원하기 위해 FSx for ONTAP 파일 시스템을 배포하려면 *배포*를 선택하십시오. link:deploy-fsx-file-system.html["FSx for ONTAP 파일 시스템을 배포하는 방법을 알아보십시오."].
** *다운로드 플랜 > VM 배포*를 선택하여 마이그레이션 플랜을 .csv 형식으로 다운로드하고, 이를 사용하여 새로운 클라우드 기반 지능형 데이터 인프라를 구축할 수 있습니다.
** 마이그레이션 계획을 .pdf 형식으로 다운로드하여 검토를 위해 배포하려면 *계획 다운로드 > 계획 보고서*를 선택하십시오.
** 마이그레이션 계획을 .json 형식의 템플릿으로 저장하려면 *계획 내보내기*를 선택하십시오. 나중에 이 계획을 가져와 유사한 요구 사항을 가진 시스템을 배포할 때 템플릿으로 사용할 수 있습니다.
