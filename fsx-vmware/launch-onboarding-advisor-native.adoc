= VMware 워크로드 마이그레이션 어드바이저를 사용하여 Amazon EC2용 배포 계획 생성
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
NetApp Workload Factory에 로그인하여 VMware 마이그레이션 어드바이저에 액세스하십시오. 마법사의 단계를 따라 사용자 요구에 맞게 사용자 지정된 배포 계획 또는 마이그레이션 계획을 생성합니다.

Workload Factory에 액세스하려면 사용자 이름과 비밀번호가 있어야 합니다. 액세스 권한이 없는 경우 지금 계정을 만드십시오. 지침을 확인하십시오 link:quick-start-vmware.html["여기"].



[[create-a-deployment-plan-based-on-an-on-premises-vsphere-environment]]
== 온프레미스 vSphere 환경을 기반으로 배포 계획을 수립합니다.

온프레미스 vSphere 환경의 현재 가상 머신 구성을 Amazon EC2의 가상 머신으로 마이그레이션하고 사용자 지정 Amazon FSx for NetApp ONTAP 파일 시스템을 외부 데이터 저장소로 사용할 수 있습니다.

.요구 사항
* link:upload-vm-inventory.html["VM 인벤토리를 업로드했습니다"]이(가) 있어야 합니다.


.단계
. link:https://console.netapp.com["NetApp Console"^]에 로그인하십시오.
. 메뉴 image:workloads-menu-icon.png["햄버거 메뉴 아이콘은 Workload Factory의 메뉴 항목인 Workloads로 이동하는 데 사용됩니다."], *워크로드* > *VMware*를 선택합니다.
+
계획 센터가 표시됩니다.

. 아직 VM 인벤토리를 업로드하지 않았다면 *VM 인벤토리 업로드*를 선택하고 link:upload-vm-inventory.html["VM 인벤토리 데이터 업로드"]의 지침을 따르십시오.
. 목록에서 VM 인벤토리 데이터 세트를 선택하고 해당 데이터 세트의 *계획 시작* 메뉴를 엽니다.
. *AWS 네이티브 컴퓨팅*을 선택합니다.
+
*AWS 클라우드 온보딩 준비* 페이지가 표시됩니다.

. _VM 구성 업로드_ 섹션에서 image:button-upload-file.png["업로드 버튼"]을(를) 선택하고 RVTools에서 생성한 .xlsx 파일을 선택합니다.
+
*데이터 수집 세부 정보* 섹션에서는 Onboarding Advisor 데이터 수집기를 사용하여 수집된 데이터의 날짜 범위 및 시간 수를 제공합니다.

+
*VM 인벤토리 요약* 섹션은 인벤토리 파일에서 채워져 VM 수와 총 스토리지 용량을 반영합니다.

. _VM 인벤토리 고려 사항_ 섹션에서 마이그레이션할 VM 목록을 필터링하는 옵션을 선택합니다.
+
.. *리전*: Amazon FSx for NetApp ONTAP 파일 시스템을 배포할 리전을 선택하십시오. 최적의 성능과 비용 효율성을 위해 일반적으로 기존 Amazon EC2 SDDC가 배포된 리전과 동일한 리전입니다.
.. 이 지역의 VM에 대한 예상 성능 수준을 선택하십시오. 처음에는 더 낮은 IOPS 설정으로 시작하는 것이 좋습니다. 파일 시스템이 생성된 후 워크로드가 마이그레이션되거나 배포됨에 따라 프로비저닝된 SSD IOPS를 늘릴 수 있습니다:
+
*** *표준~고성능*: 평균 IO 속도가 20~5000 IOPS인 VM의 경우.
*** *매우 높은 성능*: 평균 IO 속도가 5000 IOPS를 초과하는 VM의 경우.
*** *매우 낮은 성능*: 평균 IO 속도가 20 IOPS 미만인 VM에 적합합니다.




. _대상 용량 및 보호 고려 사항_ 섹션에서 몇 가지 스토리지 옵션 중에서 선택하십시오.
+
.. *VM 스토리지 고려 사항*: 온보딩된 각 VM에 대해 생성되는 데이터스토어의 크기를 현재 사용 중인 크기(권장)를 기준으로 할지 아니면 프로비저닝된 크기를 기준으로 할지 선택합니다.
+
외부 데이터 저장소는 Amazon FSx for NetApp ONTAP 파일 시스템 볼륨을 사용하여 구현될 예정입니다.

.. *평균 데이터 축소 비율*: 세 가지 일반적인 데이터 축소 비율 중에서 선택하십시오. "1:1 - 축소 없음", "1:1.25 - 20% 축소" 또는 "1:1.5 - 33% 축소"를 선택하십시오.
+
어떤 비율을 선택해야 할지 확실하지 않으면 *결정 도움말*을 선택하십시오. _데이터 축소 비율 도우미_ 대화 상자가 나타납니다. VM 인벤토리 및 스토리지 환경에 해당하는 항목을 선택하십시오. 도우미가 적절한 데이터 축소 비율을 권장합니다. 권장 비율을 사용하려면 *적용*을 선택하십시오.

.. *여유 용량 비율*: FSx for ONTAP 파일 시스템의 용량에 추가되는 용량 증가율을 백분율로 입력하십시오.
+
참고로 20% 미만을 선택하면 보호 및 장기 백업을 위한 볼륨 스냅샷을 생성할 수 없습니다.

.. *VM 스냅샷 보호*: 스냅샷을 사용하여 VM을 보호하려면 이 옵션을 활성화하십시오.


. *다음*을 선택하십시오.
. *범위* 페이지에서 AWS 마이그레이션에 포함할 VM을 목록에서 선택합니다. 각 VM의 전원 상태와 VM이 위치한 데이터 센터 및 클러스터를 기준으로 목록을 필터링할 수 있습니다.
+
VM 목록에서 열로 표시할 VM 정보 유형을 선택할 수 있습니다. 예를 들어, _예상 인스턴스 유형_을 선택하면 VM 리소스 요구 사항을 기반으로 각 VM에 대해 예상되는 Amazon EC2 인스턴스 유형이 열에 표시됩니다.

. *다음*을 선택하십시오.
. *분류* 페이지에서 VM 정보, 볼륨 분류 규칙, 볼륨 할당 및 배포의 일부로 마이그레이션될 볼륨 목록을 검토한 다음 *다음*을 선택합니다.
+

NOTE: 볼륨의 용량 또는 성능 요구 사항이 특정 리전의 Amazon FSx for NetApp ONTAP 파일 시스템의 기능을 초과하는 경우, 마이그레이션 어드바이저는 해당 볼륨을 Amazon EBS 파일 시스템에 배포할 것을 권장합니다.

. *패키지* 페이지에서 서로 다른 FSx for ONTAP 클러스터에 할당된 EC2 인스턴스와 볼륨을 검토한 다음 *다음*을 선택합니다.
. *계획 검토* 페이지에서 마이그레이션할 모든 VM에 대한 예상 월별 절감액과 비용 추정치를 검토하십시오.
+
페이지 상단에는 FSx for ONTAP 파일 시스템 및 EBS 볼륨에 대한 월별 예상 절감액이 나와 있습니다. 각 섹션을 펼치면 권장 파일 시스템 구성, 예상 절감액 내역, 가정 사항 및 기술적 고지 사항에 대한 자세한 내용을 볼 수 있습니다.

+
마이그레이션 계획은 기본적으로 계획 센터의 계획 목록에 자동으로 저장됩니다.

+
마이그레이션 계획에 만족하시면 몇 가지 옵션이 있습니다:

+
** 배포 계획을 .pdf 형식으로 다운로드하여 검토를 위해 배포하려면 *계획 다운로드 > 보고서 다운로드*를 선택하십시오.
** 클라우드 기반의 지능형 데이터 인프라를 구축하는 데 사용할 수 있도록 외부 데이터 저장소 배포 계획을 .csv 형식으로 다운로드하려면 *계획 다운로드 > 인스턴스 스토리지 배포 다운로드*를 선택하십시오.
** 권장되는 Amazon FSx for NetApp ONTAP 파일 시스템 배포를 시작하려면 *프로비저닝*을 선택하십시오.
