==== 사용자 지정 대시보드 데이터를 확인하고 새로 고침합니다.

이제 사용자 지정 대시보드 측정항목이 마지막으로 업데이트된 시간을 확인하고 수동으로 새로 고칠 수 있습니다. *데이터 새로 고침*에 마우스를 올리면 마지막 업데이트 날짜와 시간을 볼 수 있습니다.

새 스캔을 시작하려면 *데이터 새로 고침*을 선택하십시오. 배너를 통해 스캔이 시작되었음을 확인할 수 있으며, 스캔이 완료될 때까지 버튼이 비활성화됩니다.

새로운 데이터가 있을 경우 알림 배너에서 *지금 불러오기*를 선택하여 대시보드를 업데이트하십시오.

*데이터 새로 고침*과 *지금 불러오기* 모두 Tracker에서 데이터 수집 이벤트를 생성합니다.

link:https://docs.netapp.com/us-en/data-services-workloads/admin/manage-custom-dashboards-fsx.html#refresh-dashboard-data["사용자 지정 대시보드 데이터를 새로 고치는 방법을 알아보십시오."]



==== 사용자 지정 대시보드에 대한 지역을 지정하십시오

이제 맞춤형 대시보드는 요청에 지역이 포함되지 않은 경우 하나 이상의 지역을 선택하도록 요청합니다. 대시보드 데이터는 사용자가 선택한 지역으로 제한됩니다.

link:https://docs.netapp.com/us-en/data-services-workloads/admin/create-custom-dashboard-fsx.html["맞춤형 대시보드를 생성하는 방법 알아보기"]



==== FSx for ONTAP 링크 생성을 위한 IAM 정책

이제 링크 생성을 위한 CloudFormation 템플릿과 Terraform 코드는 인라인 Lambda 권한 대신 IAM 정책을 사용합니다.

link:https://docs.netapp.com/us-en/data-services-workloads/fsx-storage/create-link.html["링크를 만드는 방법을 알아보세요"]



==== AI 에이전트 동작에 대한 감사 및 추적

이제 Tracker를 사용하여 AI 에이전트 설정 변경 사항을 검토하고, 읽기/쓰기 모드에서 에이전트의 질문과 사용자의 답변을 포함한 각 승인 요청을 확인할 수 있습니다.

Workload Factory API를 통해 이루어진 리소스 변경 사항은 해당 작업을 수행하는 Workload Factory 서비스에 기록됩니다.

link:https://docs.netapp.com/us-en/data-services-workloads/admin/learn-agent.html["에이전트 작업에 대한 감사 및 추적에 대해 알아보십시오"]

==== 개시자 그룹 다이어그램 개선 사항

클라이언트 액세스 관리 페이지에서 블록 장치에 대한 이니시에이터 그룹을 표시하는 다이어그램에 이제 호스트에 대한 자세한 정보가 포함됩니다. 다이어그램에서 호스트 위에 마우스를 올리면 호스트 이름, 인스턴스 ID, 워크로드 유형, 지역 및 iSCSI 정규화 이름(IQN) 등 호스트 세부 정보가 표시됩니다.



==== 잘 설계된 이슈에 대한 이메일 개선

새로운 이메일 디자인은 Workload Factory에서 감지한 구성 문제에 대한 자세한 정보와 맥락을 제공합니다. 이메일에는 분석된 리소스 수, 경고 또는 심각한 문제가 있는 리소스 수, 그리고 해당 문제의 내용이 포함됩니다. 또한 이메일은 문제를 즉시 해결할 수 있도록 FSx for ONTAP Well-Architected 대시보드에 대한 링크를 제공합니다.



==== 잘 설계된 대시보드 개선 사항



===== 선택된 구성 검사에 대한 지원

관심 있는 구성만 분석하고 대기 시간을 줄이려면 선택한 구성에 대해 수동으로 분석을 실행할 수 있습니다.



===== 잘 설계된 분석에 대한 새로운 권장 사항

Workload Factory는 이제 FSx for ONTAP 파일 시스템에 대한 잘 설계된 아키텍처 분석에 다음과 같은 구성을 포함합니다.

스토리지 워크로드의 경우:

* *호스트를 페일오버 노드에 연결*: 활성-수동 FSx for ONTAP 파일 시스템에서 안정성을 위해 호스트가 페일오버 노드에 연결되어 있는지 확인합니다.
* *호스트를 선호 노드에 연결*: 호스트가 성능 효율성을 위해 선호 노드를 사용하여 블록 장치에 연결되어 있는지 확인합니다.
* *ARP/AI 다중 장치 감지 공백*: ARP/AI는 볼륨에 블록 장치가 하나만 연결되어 있을 때 완벽한 보호 기능을 제공합니다. 볼륨에 블록 장치가 여러 개 연결되어 있는 경우, Workload Factory는 각 볼륨에 블록 장치가 하나만 연결되도록 블록 장치를 새 볼륨으로 이동합니다.
* *클론 정리*: 스토리지 사용량을 최적화하고 비용을 절감하기 위해 30일 이상 된 볼륨 클론을 삭제할 수 있는지 확인합니다.
* *igroup OS와 호스트 일치*: I/O 또는 성능 문제를 방지하기 위해 이니시에이터 그룹(igroup)의 운영 체제가 호스트의 운영 체제와 일치하는지 확인합니다.


Kubernetes 워크로드의 경우:

* *QoS 구성*: 성능 효율성을 위해 Kubernetes 영구 볼륨이 ONTAP QoS 정책으로 보호되는지 확인합니다.
* *전용 Kubernetes 스토리지 VM*: 파일 시스템이 Kubernetes 워크로드에 대해 격리 수준을 높이고 스토리지 관리를 간소화하기 위해 전용 스토리지 VM을 사용하고 있는지 확인합니다.
* *전용 Kubernetes 내보내기 정책*: 각 Kubernetes 영구 볼륨에 클러스터의 워커 노드에서만 액세스를 허용하는 전용 내보내기 정책이 있는지 확인합니다.
* *Bidirectional CHAP for Kubernetes iSCSI backends*: Trident iSCSI 백엔드에서 보안을 위해 상호 CHAP 인증이 활성화되어 있는지 확인합니다.
* *애플리케이션 스토리지 VM에서  `showmount` 비활성화*: 클라이언트가 액세스할 수 없는 내보내기 목록을 볼 수 없도록 애플리케이션 스토리지 VM에서  `showmount`이(가) 비활성화되어 있는지 확인합니다.


데이터베이스 워크로드의 경우:

* *SAP HANA 스냅샷 정책*: 활성 데이터베이스 데이터의 스토리지 비용을 절감하고 성능을 향상시키기 위해 SAP HANA 볼륨에 대해 스냅샷 정책이 "없음"으로 설정되어 있는지 확인합니다.
* *MySQL 스냅샷 정책*: 활성 데이터베이스 데이터의 스토리지 비용을 절감하고 성능을 향상시키기 위해 MySQL 볼륨에 대한 스냅샷 정책이 "없음"으로 설정되어 있는지 확인합니다.
* *PostgreSQL 스냅샷 정책*: 활성 데이터베이스 데이터의 스토리지 비용을 절감하고 성능을 향상시키기 위해 PostgreSQL 볼륨에 대한 스냅샷 정책이 "없음"으로 설정되어 있는지 확인합니다.




===== 현재 및 권장 구성 값

잘 설계된 대시보드에서 일부 최적화되지 않은 구성에 대한 현재 및 권장 값을 볼 수 있습니다. 이를 통해 수정하기 전에 권장 값이 무엇인지 알 수 있습니다.

* 콜드 데이터 티어링
* 스냅샷 정책
* SSD 용량 여유 공간




==== 비용 개선



===== 비용 예측 및 분석

이제 비용 예측 기능을 사용하여 FSx for ONTAP 파일 시스템의 비용을 예측할 수 있습니다. 이 기능을 통해 예산을 계획하고 리소스를 효과적으로 최적화할 수 있습니다. 또한 비용 및 사용 패턴에 대한 인사이트를 확인하여 비용 최적화 기회를 파악할 수 있습니다.



===== AWS 비용 및 사용량 보고서(CUR)

Workload Factory는 이제 AWS Cost Explorer 대신 AWS Cost and Usage Reports(CUR)를 사용하여 고객 소유의 S3 버킷으로 전송되는 상세한 청구 기록을 제공합니다. CUR는 더욱 세분화된 비용 정보를 제공하며 고급 FinOps, 비용 청구 및 비용 할당 사용 사례를 위한 기반이 됩니다.



==== 스토리지 VM 마이그레이션 개선 사항

Workload Factory는 스토리지 VM 마이그레이션을 위한 향상된 안내 기능을 사용자 인터페이스 내에서 제공합니다. 여기에는 단계별 지침과 프로덕션 환경에 마이그레이션을 적용하기 전에 실행할 수 있는 테스트 실행 기능이 포함됩니다.

link:fsx-storage/create-replication.html["스토리지 VM 마이그레이션에 대해 자세히 알아보세요"]



==== 복제 지연 이메일 알림 개선

관련 복제 지연 이벤트가 대량으로 발생할 경우, Workload Factory는 이러한 이벤트를 자동으로 하나의 이메일 알림으로 통합하여 사용자가 알림으로 인해 부담을 느끼지 않도록 합니다.



==== 자동 용량 관리 향상

이제 Workload Factory에 용량을 자동으로 관리하도록 요청하기 전에 기능을 미리 사용해 볼 수 있도록 자동 용량 관리 알림을 켤 수 있습니다. 파일 시스템 용량이 부족해지면 알림을 받게 됩니다.



==== 잘 설계된 대시보드에 포함된 데이터베이스 구성

잘 설계된 대시보드에 이제 데이터베이스 구성에 대한 권장 사항이 포함되어 있어 모범 사례를 기반으로 설정을 평가하고 최적화할 수 있습니다. 대시보드에 포함된 첫 번째 구성은 다음과 같습니다:

* 콜드 데이터 티어링
* 스토리지 효율성
* 스냅샷 정책
* SSD 용량 여유 공간
* 블록 장치 공간 관리
* OS 유형
* 블록 디바이스 OS 유형을 호스트에 일치시킵니다.
* 비활성 블록 장치(LUN)
* 데이터 파일(.mdf) 배치
* 로그 파일(.ldf) 배치
* 멀티패스 I/O 상태
* 다중 경로 I/O 타임아웃
* 클러스터 쿼럼
* 컴퓨팅 적정화


Workload Factory 콘솔에서 메인 메뉴를 선택한 다음 *Well-architected*를 선택하여 Well-architected 대시보드를 찾습니다.

==== OCI NSS 시스템을 위한 잘 설계된 분석

NetApp Workload Factory에는 OCI NSS 시스템을 위한 well-architected 평가가 포함되어 있습니다. 이 평가는 운영 우수성을 달성하는 데 도움이 되는 통찰력, 권장 사항 및 수정 사항을 제공합니다.

OCI 웰 아키텍처 프레임워크의 다음 핵심 요소에 대한 구성 평가를 이용할 수 있습니다:

* 안정성: 파일 오브젝트 용량, 스냅샷 정책 및 SSD 용량 여유 공간
* 운영 우수성: 호스트에서 확인 가능한 용량 보고 및 볼륨 용량 여유 공간
* 비용 최적화: 콜드 데이터 계층화, 스냅샷 정리 및 스토리지 효율성


link:https://docs.netapp.com/us-en/data-services-workloads/oci/add-credentials-oci.html["OCI NSS 시스템에 대한 잘 설계된 분석"] 및 link:https://docs.netapp.com/us-en/data-services-workloads/oci/improve-configurations.html["잘 설계된 구성 구현"]에 대해 자세히 알아보십시오.
